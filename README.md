## 📌 Какая стояла задача и какую боль закрывали

### Проблема (Боль):
В Go запустить горутину тривиально (`go func()`), но в нагруженном бэкенде это частый источник критических проблем:
- **Утечки горутин (Goroutine Leaks):** зависшие горутины, ожидающие данные в незакрытые каналы, не освобождают память и приводят к OOM-киллеру в продакшне.
- **Data Races:** несинхронизированный доступ к общим структурам памяти разрушает состояние данных.
- **Неконтролируемый параллелизм:** спавн тысяч горутин на каждый входящий запрос перегружает планировщик Go (GMP) и забивает сеть.

### Решение:
- Собрана и протестирована коллекция проверенных паттернов безопасного управления конкурентностью:
  - Ограничение параллелизма через пулы воркеров (Worker Pools).
  - Оркестрация группы задач с прерыванием по ошибке через `errgroup`.
  - Алгоритмы ограничения частоты запросов (Rate Limiting).
  - Потокобезопасные структуры данных на примитивах `sync.Mutex` и `sync.RWMutex`.
  - Валидация каждого модуля встроенным детектором гонок Go (`-race`).

## 🏗 Обзор модулей и паттернов

```
hello/
├── workers/        # Классический Worker Pool: распределение очереди задач между фиксированным числом горутин
├── pworkers/       # Конвейерная обработка данных (Pipeline Pattern) с буферизированными каналами
├── errgroup/       # Оркестрация параллельных подзадач с отменой по контексту при первой ошибке
├── semafor_err/    # Контроль конкурентности с использованием семафоров и перехватом ошибок
├── ratelimit/      # Алгоритм ограничения частоты вызовов (Rate Limiter) на тикерах time.Ticker
├── structbank/     # Потокобезопасная банковская модель: защита баланса от Race Conditions через sync.Mutex
├── buffers/        # Эффективная потоковая работа с буферами памяти
└── wordcounter/    # Параллельный подсчет и редукция данных (Map-Reduce примитив)
```

## 🛠 Ключевые библиотеки и примитивы

| Примитив / Пакет | Назначение |
|---|---|
| **`sync.WaitGroup`** | Ожидание завершения группы независимых параллельных воркеров |
| **`sync.Mutex` / `sync.RWMutex`** | Взаимное исключение при конкурентном изменении общих структур |
| **`golang.org/x/sync/errgroup`** | Синхронизация группы горутин с возвратом первой возникшей ошибки и отменой общего контекста |
| **`context.Context`** | Проброс сигналов отмены (cancellation) и таймаутов в фоновые задачи |
| **Буферизированные каналы** | Асинхронная передача сообщений с защитой от блокировки продюсеров |

## 🧪 Запуск и проверка на состояния гонки

Все примеры рекомендуется запускать с включенным флагом детектора гонок:

```bash
# Проверка модуля потокобезопасного банка
go run -race structbank/main.go

# Запуск оркестратора задач с errgroup
go run -race errgroup/main.go

# Запуск конвейера воркеров
go run -race pworkers/main.go
```
